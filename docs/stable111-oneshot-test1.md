# 1.1.1 一次性任务修复测试 1

基线：正式 tag `refactor-v1.1.1`，提交 `be39f598bfb921526851c5c4a2e92905dacf4ea7`。
未合并 PR249 / Test10，未修改 main，未发布正式版本。

## 本轮范围

- HyperOS SVG 字体：跳过会要求 lxml 的轮廓子集压缩，保留 SVG 原始表和字形编号；仍执行可证明的字符路由和度量处理。不删除 SVG，不伪造 lxml，不修改用户原始字体。含 SVG 的字库可能较大。
- 导入／选中字体的预热兼容入口变为空操作，不再生成独立预热任务；明确应用时仍保存、复用已完成的缓存。
- Google/主题字体服务改为开机单次处理，最多 180 秒（含等待开机），不自动重启应用，不启动常驻观察循环。后来下载的字体／新的隔离命名空间不会被持续补换。
- 独立任务由一次性标准库管理进程监督，使用 Linux subreaper 回收脱离进程组的子孙进程；正常、异常、信号和超时路径都执行清理。只向验证了 PID 启动时间的自有子孙发信号，不使用全局 killall/pkill。
- PID 记录由管理进程在清理完成后删除，保存 `config/<worker>.pid.cleanup.json`。`leftoverPids` 非空时返回错误 125，不能声称成功回收。
- 任务整体上限默认 900 秒；已有单字体 360 秒和组合生成 480 秒限制未删除。超时只额外允许最多 3 秒收尾。新逻辑没有新增常驻守护进程。
- 字体缓存版本更新，并把实际 Python 映射器加入缓存身份，避免旧缓存跳过本次修复。

## 验证边界

使用 1.1.1 正式模块中原样提取的 FontTools 4.63.0，在 Linux 主机验证。
专项测试 13 项、HyperOS CJK 路由 24 项、HyperOS 度量 17 项、ColorOS 度量 13 项，共 67 项。
专项进程测试实际启动父子进程及另起会话、忽略 TERM 的子进程，检查成功、失败、超时、HUP/INT/TERM 之后无存活或僵尸子进程，并保持无关进程存活。

尚未在 Android 真机运行。未复现用户评论中的具体发热进程，没有完整的故障字体、tombstone/logcat 或 OS4 原厂字体清单。
状态栏变细、等宽字体替换、锁屏／系统应用覆盖、Chrome 和中国体育彩票崩溃或网络提示均不标记为已修复。
旧常驻观察服务相关测试约定与本轮要求相反，完整旧测试套件尚未适配，也没有宣称全仓 CI 通过。

## 测试包

测试包只覆盖模块脚本；内置 App APK 仍为 1.1.1 正式版原字节、原签名。
包的名字标记为“无常驻测试1”，版本码保持 60101；不增加新的正式发布号或在线更新。
覆盖刷入后完整重启，不能只关闭 App 来替换已经运行的旧脚本。
关注应用完成／失败后对应 `.cleanup.json` 的 `leftoverPids` 和 `result`，以及随后是否仍有持续 CPU 占用。
出现发热或新异常时，在 Root 管理器禁用模块并完整重启；不要批量杀系统 Python/sh 或系统 UI 进程。
